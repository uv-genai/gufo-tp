# Gufo-TP v0.33.0 upstream integration — November 11, 2026

Release tag: `tp2-rdma-merge-v0.33.0-2026-11-11`.
This Linux TP2 source release integrates upstream v0.29.0 through v0.33.0
since `tp2-rdma-fixes-v0.28.1-2026-11-06`. It preserves the previous reasoning,
cache-control, signed Q8 projection and metadata-only Q4 shard fixes.

## Changes

- Source-extension migration with the native mirrored TP2 snapshot/fork and
  RAM/disk restore contracts retained. Source extension API is **0.2.22**.
- Provider sampling defaults, tool dialects, reasoning markup and legal prefill
  frontiers propagate through the mirrored runner and control protocol.
- Upstream prefill scheduling, shared-expert overlap and startup calibration
  are integrated for one host. TP2 retains bounded mirrored prefill calls;
  callbacks and calibration cannot introduce unmirrored collectives.
- Snapshot-copy registration-boundary and cache-retention repairs, strict
  tool-schema/reasoning-budget fixes, `/tokenize`, provider options and the
  shared Rust PNG/WAV decoding build are integrated.
- README, native setup, TP2 design, handoff and agent instructions describe the
  current layout, build prerequisites, deployment and qualification limits.
  Qwen3.8 27B Q8 remains prohibited; the current GPU scope is Flash-Next.

Both Strix Halo hosts have the same `build/release/gufo`:

- Compiled source: `b325c75c7c602020784e1fa48f9b8290f74c3aa4`.
- SHA-256: `85f0be16d16ac11b8933b968ce6e4c060d6538c4ec51ed3938232e323b50d7a7`.
- The annotated tag identifies the released source tree. Its production code
  matches the validated executable; later changes are documentation/evidence.
  The deployed executable reports its compiled development revision.
- This release provides source archives and notes, with no installable binary
  asset. Native build instructions are in [BUILD-LOCAL.md](../../BUILD-LOCAL.md).

Upgrade **both ranks together**. TP control protocol is **23**, snapshot
payload is **20**, and compatible persisted states include the static YaRN
position-policy identity. Older peers are rejected; incompatible cache states
miss and are rebuilt. Both hosts need identical target shards, MTP sidecar and
projector. TP2 keeps component-cache restore, draft subsets, prompt copies,
deferred residuals, dynamic YaRN re-rotation and layer yields disabled.

The deployed llama-swap wrapper is `tools/llama-swap/tp2.sh`. Q4/Q8 launchers
default to two sessions, context capacity 524288, static YaRN factor 2 and MTP.
The API is on port 8080; query `/running` for the assigned backend port.
These capacity settings do not establish full-depth context quality.
Preserve existing user sessions and allow only one model process per GPU host.

## Known limits

Q4's v0.33.0 initial timing comparisons are within the 5%/10 ms limits.
Some Q8 measurements remain **inconclusive and unqualified** after focused
main/candidate/main controls and diagnostics. The v0.32.0 large uncached
prefill outlier and v0.33.0 short-prefill flag did not recur in their diagnostic
captures; their causes remain unresolved. Instrumented timings are excluded
from speed qualification. No speedup or performance-fix claim is made.

The existing sparse-prefill numerical envelope remains; a historical full-model
split probe reports maximum logit difference 0.698152. This release does not
establish byte-identical logits across every chunk layout. Full 524288-token
context depth, Q8 image behavior and other model families were not requalified
by the final MTP scope. Windows is outside this Linux qualification.

The earlier client `Error generating response body` remains unreproduced and
is not claimed fixed. Historical user-reported speeds and benchmark tables
retain their original dates and are not measurements of this release.
