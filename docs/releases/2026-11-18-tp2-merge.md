# Gufo-TP v0.35.0 upstream integration — November 18, 2026

Release tag: `tp2-rdma-merge-v0.35.0-2026-11-18`.
This Linux TP2 source release integrates upstream v0.35.0 since
`tp2-rdma-merge-v0.34.0-2026-11-17` and fixes the intermittent TP2
`verbs communicator is poisoned` failure. It keeps all earlier TP2 fixes and
gates.

## Changes

- **TP2 fix** ([#40](https://github.com/uv-genai/gufo-tp/pull/40)): the
  intermittent `verbs collective identity or size mismatch` during MTP decode.
  Upstream v0.28.1's confidence gate ends greedy draft chains early, but the
  split greedy draft head downloaded only its token, so each rank gated on a
  host word that path never wrote. The ranks could stop one chain at different
  widths: a one-row draft exchange then met a multi-row verification. The
  exchange row now carries each half's softmax normalizer, so both ranks
  compute the same confidence. No collective is added. Q4 and Q8 are both
  affected (both heads are Q8_0).
  - The fix also lifts a cap: single-request greedy drafting had been stuck at
    one proposal per round.
  - TP control protocol **24** rejects peers without the fix.
- Upstream v0.35.0 ([#41](https://github.com/uv-genai/gufo-tp/pull/41)):
  - A required text scheduling profile replaces the legacy prefill budget.
    TP2 declares one unsplit 512-token pass beside decoders, its former width,
    with no layer yields.
  - XDNA NPU execution for EmbeddingGemma 2, Qwen3-ASR and Qwen3-TTS (`--npu`).
  - A Q4_K copy of the MTP draft-head prefix for single-host drafting.
  - The A1111 (`sdapi`) image API, Qwen-Image true CFG and image-to-image.
  - Trimming of the reasoning separator after a prompt-closed block.
  - Cache retention, recovery and transfer-stream fixes.
  - Multipart parsing per RFC 7578, a breaking upstream change.
  - Source extension API **0.3.20**.
- **Build:** upstream now requires XRT at configure time. On Linux, a host
  without XRT builds without the NPU module, with a warning, and serves on the
  GPU; NPU requests then report that XRT is unusable.

Upstream commits after the v0.35.0 tag are excluded.

- The fix reproduces and resolves on hardware. A Q4 TP2 pair on the v0.34.0
  binary poisoned with the production signature (`20480` against `10240`).
  The same workload passes on the fix, with every reply both runs finished
  byte-identical. On Q8, all 60 probe replies match, and single-request greedy
  drafting rises from 1.000 to 2.574 proposals per round (44.2 → 57.4 tok/s).
  [Probe evidence](../internal/models/qwen3.8-flash-next/artifacts/tp2-draft-confidence/probe-results.json).

## Known limits

Timing is **inconclusive and unqualified**. The initial flags (Q8 long
prefill, warmup and short-code-cached decode; small `std0` phases) do not
recur in the fix/candidate/fix repeat. The unchanged fix binary varies by up
to 28% against itself on short phases. In a two-session probe, two early
greedy requests stayed 6–13% slower on the candidate in both alternated runs.
No regression is confirmed and no speedup is claimed. The single pp2048/tg128
rates (Q8 decode 36.0 → 42.0 tok/s) are observations, not a qualified gain.

NPU execution is not built on these hosts and was not tested. The Qwen3.8 27B
in-pass capture adaptation and the Nix package changes were not run. The
sparse-prefill numerical envelope and the 0.698152 split-probe logit
difference remain. Full-depth context, Q8 images, other model families and
Windows were not requalified. The earlier client `Error generating response
body` remains unreproduced.
