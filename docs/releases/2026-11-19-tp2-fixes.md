# Gufo-TP v0.35.0 TP2 fixes — November 19, 2026

Release tag: `tp2-rdma-fixes-v0.35.0-2026-11-19`.
This Linux TP2 source release follows `tp2-rdma-merge-v0.35.0-2026-11-18` on
the same upstream v0.35.0 base. It fixes a TP2 failure when two or more
requests decode concurrently, splits the sampled draft head across both ranks,
and adds a multi-agent benchmark. It keeps all earlier TP2 fixes and gates.

## Changes

- **TP2 fix** ([#44](https://github.com/uv-genai/gufo-tp/pull/44)): with two
  or more requests decoding concurrently, the pair could poison its verbs
  communicator (`verbs collective identity or size mismatch`, 10240 against
  20480 bytes) and both servers exited. The launchers' default two sessions
  are enough to trigger it.
  - Cause: with two or more requests still drafting, each rank scored the
    full draft head for every request and gated each chain on its own logits.
    A rank-local value near the gate ended one rank's chain early: its single
    split head (a one-row exchange) met the other rank's two-row draft body.
    A single request's head already split and exchanged these values.
  - Fix: each rank scores its half of the vocabulary for every batched
    request, and every request's half takes its own slot of one all-reduce
    row, so both ranks merge the same data.
  - TP control protocol **26** rejects peers without the fix.
- **TP2 performance** ([#43](https://github.com/uv-genai/gufo-tp/pull/43)): a
  sampled draft scored the full 248,320-row Q8_0 head on both ranks. Each rank
  now scores its half and selects its top 64 candidates; both lists cross in
  one all-reduce row and both ranks merge them into the exact full-vocabulary
  top 64. Protocol 25 introduced this; 26 includes it.
- **Benchmark** ([#44](https://github.com/uv-genai/gufo-tp/pull/44),
  [#45](https://github.com/uv-genai/gufo-tp/pull/45)): a multi-agent
  concurrency benchmark, recorded in
  [BENCHMARKS.md](../internal/models/qwen3.8-flash-next/BENCHMARKS.md#multiple-coding-agents-november-19-2026)
  and summarized in the README.

## Binary identity and upgrade

Both Strix Halo hosts have the same `build/release/gufo`:

- Compiled source: `1593d7e0c02d408cafef5242f36bfde1b36245f3`.
- SHA-256: `0b75c5aaa3a043626508bfea5aeb0b1a6afc58556311131973df60076ad1394c`.
- The annotated tag identifies the released source tree. Its production code
  matches the validated executable; later commits change only documentation
  and evidence. The executable reports its compiled development revision.
- This release provides source archives and notes, with no installable binary
  asset. Native build instructions are in [BUILD-LOCAL.md](../../BUILD-LOCAL.md).
  The binary was built without XRT and needs libopus at runtime.

Upgrade **both ranks together**. TP control protocol is **26** and snapshot
payload is **20**; older peers are rejected. Both hosts need identical target
shards, MTP sidecar and projector. For rollback, both hosts retain the
protocol-25 binary at `artifacts/split-sampled-head-2026-11-18/gufo-candidate-split`
(it has the concurrent-request failure: use `SESSIONS=1` with it) and the
v0.35.0 binary at `artifacts/upstream-2026-11-18/gufo-candidate-v0.35.0`.

The deployed llama-swap wrapper is `tools/llama-swap/tp2.sh`. Q4/Q8 launchers
default to two sessions, context capacity 524288, static YaRN factor 2 and MTP;
a third concurrent request waits for a session, so set `SESSIONS=4` for up to
four agents. The API is on port 8080; query `/running` for the assigned
backend port.

## Validation

Evidence for #44 used the released binary; evidence for #43 used its
predecessor `c28b59d7…` (compiled source `3ea2bc10`), whose code is included
unchanged.

- **#44 on hardware.** On the unchanged build, the multi-agent benchmark
  poisoned the pair in 2 of its first 5 C3 levels, and a control run just
  before the fix runs poisoned at C2 after 14 levels. On the released binary,
  all 48 levels completed (Q8 once, Q4 twice) with clean rank logs. Replies
  match the unchanged build at every level it completed.
  [Evidence](../internal/models/qwen3.8-flash-next/artifacts/tp2-batched-split-head/results.json).
- **#44 checks.** `mtp_ops` shows each batched slot bit-identical to that
  request's single exchange at 2, 3, 5 and 8 requests, greedy and sampled
  mixed. TP2 probes match main 30/30 on Q8 and Q4 with identical sequential
  draft counts. **394 Flash-Next TP2+MTP functional checks** pass (182 Q8,
  212 Q4) with disk restore after restarting both ranks.
- **#43 checks.** `mtp_ops` matches the full candidate selection bit for bit
  at vocabularies 2–248,320. TP2 probes match main 30/30 on Q8 and 29/30 on
  Q4; the one Q4 reply also differs between two runs of unchanged main. 394
  functional checks pass. On 768-token probes, unprofiled sampled decode rose
  3.4–7.8% on Q8 (mean 5.3%) and 0.5–4.1% on Q4 (mean 2.6%).
  [Evidence](../internal/models/qwen3.8-flash-next/artifacts/tp2-split-sampled-head/results.json).
- Native CPU PR contracts pass **134/134** and the TP2 RDMA release build
  passes. Formatting passes with clang-format 21.1.8 and 23.1.1. The docs and
  extension API checks pass.
- **User reports**, separate from the matched benchmarks: through llama-swap,
  the #43 binary ran one long sampled Q8 generation at 50.5 tok/s against
  39.0 tok/s on v0.35.0 the day before (one uncontrolled run each), and the
  released binary worked with similar performance, generating above 50 tok/s
  on Q8.

## Known limits

- The value that diverged between ranks in #44 was never captured: debug
  builds rarely failed (1 in about 34 C3 levels). The fix rests on the matched
  signature, the hazard analysis and the 48 clean levels.
- Target verification rows still read the full head on both ranks; they are
  not exchanged.
- One Q8 concurrent greedy reply differs from its single-request reply, at the
  level where the unchanged build failed; both ranks produced it alike.
- Single requests remain occasionally run-to-run nondeterministic (a seeded
  sampled reply and a Q4 greedy probe reply), under separate investigation.
- Timing is **inconclusive and unqualified**. #44's combined C2–C4 gain of
  0–8% is mostly within the ±4% spread between two starts. Q4 functional timing
  flags std1 prefill and TTFT (+5.9%), a single-request prefill that never runs
  the changed path. #43's Q4 timing stayed inconclusive.
- NPU execution, Qwen3.8 27B, full-depth context, Q8 images, other model
  families and Windows were not requalified.
